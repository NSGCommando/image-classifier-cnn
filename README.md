# Image Classifier #
- A CNN-based image classifier trained on Fashion-MNIST dataset. Dataset contains 60000 training and 10000 test images over 10 classes. 
- Top-1 accuracy overall(evaluation) after 10 epochs training is approximately 90-92%
- Fully dockerized API served over HTTP via Docker Compose
- Multi-image capability handled through multi-worker job queue.

## Architecture ##

### Model Structure ###
- Input layer with input shape of 28x28 pixels per image
- Two blocks of Conv2d layers, blocks structured as follows: ```COnv2d -> BatchNorm -> ReLUActivation -> MaxPooling```
- Conv2d blocks followed by two dense layers of 128 and 256 neurons each, second dense layer has L2 Regularization applied to it
- Final layer is dense layer for classification with 10 output neurons and Softmax activation
- Inference script has checks for white-background images, and will flip image arrays if it is detected that the image has high intensity backgrounds to help classify input images
- Can be run in CLI mode locally as well as over HTTP via Uvicorn server

### Server Setup ###
- Deployment setup as follows:
 - `Orchestrator`:
   - -> `CLI Mode` -> `CLI Inference`
   - -> `Server Mode` -> `Dispatcher Server` -> `Inference Workers`
- Orchestrator selects whether to load CLI inference scripts or start HTTP server and inference workers for server inference
- CLI Mode loads CLI inference scripts with output logged to console
- Server Mode starts Dispatcher server and inference workers as non-blocking asyncio tasks
  - Server mode also includes a asyncio task to trim the Redis Job Stream
- Data flow through the architecture is as follows:
 - `File Upload to Dispatcher API` -> `Dispatcher` -> `Job Stream` -> `Inference Worker` -> `Result Stream` -> `Result API`

## Training ##
- To train the model and generate model weights, run the `training.py` script from project root as follows: `python training.py`
- Model exported to `src/models/Exported_Model/`
- Model best accuracy stored at `src/results/eval_accuracy.txt`

## Inference ##
- Single source execution managed in `run.py` and orchestrated via `run.bat`.
- Server API orchestration via Docker Compose also provided.
- Inference done via Asyncio tasks that use a shared model session
- Uses ONNX runtime for small, lean inference image size (~530 MB Docker Image)

## ONNX ##
- After training, model exported to `src/models/Exported_Model` as `saved_model.pb`
- Run `python -m src.scripts.tf2onnx_convert` to convert the saved model to .onnx format, stored as `onnx_model.onnx`
- ONNX runtime is significantly smaller as compared to Tensorflow for the purposes of model inference, leading to faster and lighter Docker Image

### Run Inference Servers ###
- Ensure a Redis instance is running and available at `localhost:6379`. You can use global Redis instance or Docker container exposed to port 6379. 
  - No need to manually start a Redis instance if running the app via Docker Compose
- Run `Uvicorn` dispatcher and inference servers via `run.bat --server [x]` from project root, where 'x' is number of inference workers to start 
- Access the dispatcher API at `localhost:8000/api/dispatcher` and result API at `localhost:8000/api/dispatcher/results/{batch_id}`
  - The dispatcher API returns a status message with a `batch_id` after successful file upload.
  -  Note that results API requires this `batch_id` to be appended in place of `{batch_id}` in the API URL to retrieve the corresponding results.
    - Example - `http://localhost:8000/api/dispatcher/results/21cd0dfd-43e6-4ca3-90b3-928f8d911beb`
- Test the API functioning for both APIs via opening `localhost:8000/docs`; this is an autogenerated page using OpenAPI specifications for API documentation
- HTTP Inference works on both single images and zip files containing images
- Alternatively, run `docker-compose up --build` from root to build and run a docker image for the inference API server (default creates two inference workers).

### Run CLI Inference ###
- To run CLI inference on a single image or a zip file, use the following command in terminal from the root folder: ```run.bat --file [image_path/Zipfile_path]```
- To run CLI inference on a group of images in a local directory, use `run.bat --folder [image_folder_path]`; the app will handle collection of all valid images within the provided folder. (Valid images are ".webp", ".jpg", ".jpeg, ".png")
- Batch script handles orchestration for .venv activation

## Implemented ##
- Training with Weight Loading and Saving for best weights
- Single-Image Inference (Both CLI and HTTP)
- Multi-Image CLI Inference (via Directory Globbing)
- Multi-Image HTTP Inference (via Zip handler logic)
- Handle Byte-streams and FilePaths (via strategy Pattern dispatcher)
- Multi-worker Inference (using Asyncio tasks) and Job Co-ordination (via Redis Streams)
